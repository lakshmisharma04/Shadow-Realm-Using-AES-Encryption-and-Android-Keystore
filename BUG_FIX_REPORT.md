## Security fixes found during the audit
* `DELETE /vote/clear` let **any logged-in user wipe every room's votes** -> removed.
* `GET /vote/{room}` exposed vote choices -> it now returns only the authenticated caller's own counted votes. `/most-voted` never returns a leader and rejects requests while a council is open.
* `GET /game/{room}`, `/player/{room}`, `/player/{room}/alive` required only a login -> now require membership of that room.
* Night/vote endpoints return small DTOs instead of raw entities. No secret words or hidden roles appear in any public response.
* Registration no longer binds a JPA `User` directly from untrusted JSON. It normalizes email/username, rejects duplicate usernames, and stores only a BCrypt password hash. BCrypt's 72-byte input limit is checked.
* Removed weak JWT/AES key fallbacks. The server now requires independent secrets of at least 32 UTF-8 bytes. JWTs are checked against a per-user token version; changing a password checks the current password, returns a replacement JWT, and invalidates older tokens.
* Room creation validates the 4–7 player limit. Room joins/start are serialized with database row locks, room membership/host status are derived on the server, and a room cannot be deleted or left after its match starts.
* Corrected API responses that Android's Retrofit models could not parse, including room deletion and the no-leader case. Chat now returns the newest 100 messages in chronological order.
* Removed the OTP screen's hardcoded demo-token sign-in; it now clearly returns to sign-in because the backend has no OTP verifier. Android backup is disabled for local token/session preferences.

## Known remaining issues / design notes
* No automatic AFK detection or timeout. A host can resolve a stalled council using submitted votes; missing votes are abstentions.
* Offline matches are not stored in history (history is server-side, online only).
* OTP verification and password reset are not implemented by the backend.
* Local Android configuration uses HTTP for emulator/phone development. Configure HTTPS before exposing the API to an untrusted network.
* `ddl-auto=update` is used for schema changes (as in the original project); no Flyway/Liquibase was introduced.
* Verification limits and exact build/test results are in `TEST_REPORT.md`; MySQL-backed and Android-device flows were not available in this environment.
